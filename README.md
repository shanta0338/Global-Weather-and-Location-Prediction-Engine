# Weather → Location/Country Predictor (Streamlit)

Predicts `location_name` or `country` from 10 numeric weather measurements
only, using the exact architecture from `Location_Prediction.ipynb`:

```
Linear(10, 256) → ReLU → Dropout(0.2) → Linear(256, 128) → ReLU → Linear(128, n_classes)
```

Features used: `temperature_celsius, wind_kph, wind_degree, pressure_mb,
precip_mm, humidity, cloud, visibility_km, uv_index, gust_kph`.

## Folder contents

```
streamlit_app/
├── GlobalWeatherRepository.csv
├── train.py        # preprocessing + training -> artifacts/
├── app.py           # the Streamlit app
├── requirements.txt
└── artifacts/        # generated by train.py

    ├── location_classifier_country.pth
    ├── scaler_location_name.joblib
    ├── scaler_country.joblib
    ├── label_encoder_location_name.joblib
    ├── label_encoder_country.joblib

    └── sample_rows.csv
```

`artifacts/` is already trained and included, so you can run the app
immediately without retraining.

## A note on the notebook

Your notebook controls which target it trains via a `target_col` variable
(set to either `TARGET_LOCATION` or `TARGET_COUNTRY`) — only one model is
trained at a time when you run it top to bottom. `train.py` runs that same
exact pipeline twice (once per target) so the app can predict either one
from a dropdown, without you needing to re-run the notebook and retrain by hand.

Also: the notebook reads from a local Windows path
(`D:\My Folder\Dataset\GlobalWeatherRepository.csv`) — `train.py` reads the
CSV from the same folder it lives in instead, so it runs anywhere.

## Setup

```bash
cd streamlit_app
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## (Optional) Retrain

```bash
python train.py
```

Reruns both targets for 10 epochs each (matching the notebook) and
overwrites `artifacts/`. On this machine: **39.4%** test accuracy for
location, **39.5%** for country. This is expected and not a bug — with only
weather measurements as input (no latitude/longitude or timezone), location
isn't fully recoverable; many places around the world share similar weather
on a given day. If you want noticeably higher accuracy, the fix is adding
location-correlated features (lat/long, timezone) back in — happy to wire
that up if you want it.

## Run the app

```bash
streamlit run app.py
```

Opens at `http://localhost:8501`. Pick **Location name** or **Country** at
the top, then either:
- **Predict from a real example** — choose a sample row and compare the
  prediction to the actual answer.
- **Enter values manually** — type in your own weather measurements and get
  a live top-5 prediction with confidence bars.
